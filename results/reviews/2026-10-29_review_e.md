## Blockers (before the loop runs)

### B1. The first tactic is judged against a baseline of whole-block scores, so correct first tactics are pushed down
`rl/grpo_groups.py:77-87` (`score_parts`), `rl/advantages.py:55-60,73-80`; DESIGN.md:581-586.

b is the mean of final-state scores, and those include the δ gains of later tactics. The first tactic, however, gets
R(s1) − b, where R(s1) carries only one step of progress. So the expected first-tactic advantage in a group is
mean R(s1) − mean score = −E[Σ later gains] < 0 whenever blocks go more than one step. The telescoping keeps each
sample's sum correct but moves the blame onto the first tactic:

- Verified (`credit_scenarios.py`): at a node with d = 4, if 6 of 8 samples prove it in one 4-tactic block and 2 fail,
  b = 1.21. The correct first tactic that every proof shares gets **−0.161**, the later tactics +0.2, the explanation
  +0.45. At d = 10 (one full-proof sample, one one-step sample, one failure), both correct first tactics get −0.2.
- Effect: in exactly the groups where the policy does best (multi-tactic proofs, which the mixed-length SFT chunks
  teach), the tokens of its correct first moves get negative advantage on every sample. Advantages with a non-zero
  mean also raise variance and push probability mass toward unsampled tokens.
- Fix: give each part its own baseline. The explanation keeps score − b. The first tactic gets R(s1) − b1, with b1 the
  multiplicity-weighted group mean of R over the samples' first known states. Later tactics keep their gains. Add a
  test that a correct first tactic shared by all proofs is never negative when every other sample fails.

### B2. The μ switch is a coin flip, and a value model that hurts the search is never rolled back
`rl/evaluation.py:189-211` (`passed` at 208), `rl/loop.py:788-805`, `loop.toml` `[evaluation.value_ab_test]`;
DESIGN.md:758-760.

The rule is `difference >= 1 and worse_p_value >= 0.05`. Whenever the difference is ≥ 1, only_published >
only_reference, so `worse_p_value = P(X ≥ only_reference) > 0.5`. The second clause can therefore never bind, and the
rule reduces to "solved at least one more problem out of 250".

- Verified (`ab_null.py`): two identical arms pass **48%** of the time (mean of 42 to 62 discordant problems). The A/B
  runs every 12 h and μ never switches back off. So once any model has passed gate (a), μ = 0.15 turns on almost
  surely within a few days whatever the model's quality. DESIGN.md itself puts the chance that a no-gain candidate
  passes (a) at 2–4% per retrain; with a retrain every 4 phases over a multi-day loop, at least one such pass is
  likely. This is the noise-driven μ flip review D warned about, reached by a longer path.
- Separately, publication (which steers every loop search and therefore the data and the harvest) depends only on
  gate (a). Gate (a) measures sibling order and is blind to calibration across branches, which A* also uses. A/B (b)
  can only turn μ on. If it finds the published model clearly worse than v0, nothing happens (`run_value_ab` acts
  only on `passed`).
- Fix: require evidence, e.g. one-sided McNemar p_better < α (0.05–0.1), or the solved difference above the measured
  v0-vs-v0 noise from the two baseline probe runs. Pool the discordant problems of repeated A/Bs of the same published
  version. If the A/B finds the published model worse at p < 0.05, republish v0's value adapter (or the last one that
  passed) and log it. A further option is the DESIGN's (ii): let the A/B gate publication itself.

## Major

### M1. Host memory during value phases: four ranks each hold eight phases of trees while 112 REPLs stay alive
`experiments/grpo_phase.py:68-76,86-94`, `rl/training_phase.py:334`, budget at `rl/README.md:287-306`. Plausible,
not measured.

Every rank reads and labels the whole value window (8 phases of trees with per-tactic `tactic_goals`; goal strings
are non-ASCII, so Python stores them at 2–4 bytes per character). The paused searches' REPLs are stopped only before
evaluations, not before training (`loop.py:806-814` vs `finish_phase`). The budget formula has no term for the
training job. The first full window arrives at phase 8, after the planned first-hour memory checks. An OOM-killed
rank makes torchrun fail and the loop stop. On restart the same data is loaded again, so it fails the same way.
Fix: measure RSS per rank in the phase-4 value training. Stop the paused REPLs before training as well (they already
replay their states), or build `GraphValueData` once on rank 0 and broadcast the tokenized states. Add the training
term to the budget.

### M2. A later tactic that is valid but leaves the proof graph costs ~8–10× a later Lean error; the stop analysis omits this
`rl/grpo_groups.py:157-171`; DESIGN.md:596-604, `phase.toml` comment on 1/3.

Verified: proof graph, then off graph scores 0 (that tactic gets −1.05). Proof graph, then a failure scores 0.95
(−0.1). This is consistent with what the search keeps (the error leaves the proof-graph prefix as the child). But the
claim "continue when P(correct) > 1/3" holds only if off-graph outcomes never happen. With a probability q_off of a
valid move off the graph, the condition is 0.2·p − 0.1·f − 1.05·q_off > 0. This pushes blocks shorter more strongly
than documented, and it ranks "valid but wrong direction" far below "does not compile". Stopping still dominates
deliberate errors, so the policy cannot exploit it, but it can learn to stop early. Fix: either cap a later tactic's
drop (e.g. at −(c + δ)) or correct the DESIGN's threshold and watch the block-length chart from phase 1.

### M3. Restart wakes the servers before it checks for an orphaned training job; torchrun workers sit outside the recorded process group
`rl/loop.py:488-497` (`servers.serve(current)` and `finish_phase` come before `run_logged`'s `live_children` check at
`loop_services.py:154`). torch 2.13's `SubprocessHandler._popen` uses `start_new_session=True` (verified), so the
workers are not in torchrun's group. The `killpg(SIGKILL)` fallback (`loop_services.py:145-148`) therefore never
reaches them.

Scenario: torchrun is SIGKILLed (OOM, or the 30 s escalation fires while torchrun is still shutting down its workers)
and its ranks keep their GPUs. On the next loop start, all eight vLLM servers wake into that memory, and the wake or
the new trainer OOMs. Fix: run the `live_children` check (and a check of GPU memory in use by non-vLLM processes) at
the start of `session()`, before `serve()`. Set PDEATHSIG in the workers, or record their PIDs.

## Minor

1. **Unbounded negative progress** (`grpo_groups.py:144`). A valid tactic reaching a proof-graph state k steps farther
   gets R = 0.85 − 0.2k. That is below an off-graph state (0) at k ≥ 5 and below a Lean error at k ≥ 6. Verified: from
   d = 1 to a state with d = 7, R = −0.35 against −0.15 for an error. Harvesting makes long alternative routes more
   likely. Clamp the proof-graph R at ≥ the off-graph value. Related: G is no longer in [0, 1]. Group advantage scale
   grows with d(node) (failure at d = 10 gets −1.4, at d = 1 −0.8), so without std normalization, root groups of long
   proofs dominate, and the stated ~15% local share no longer holds there. Report the local share by d.
2. **Two anchors break the "advantages add up to score − b" identity** (`score_parts`). A no-op or redundant first
   tactic leaves `state` None, so the next proof-graph tactic is anchored against b again. Verified: tactics
   [−0.8, +0.4] against score − b = +0.4, which counts b twice. Defensible (the no-op is penalised), but
   DESIGN.md:586 and rl/README.md:69 state the identity unconditionally.
3. **The goal bonus is a transition reward that is telescoped like a state value.** Within a block, the tactic after
   a goal-closing tactic gets −0.015, and only the last tactic's closings reach the score. This is negligible but
   unintended. Trailing `done`/`try` after a nested proof closed are labelled no-progress and cost −c each, which
   teaches the policy to drop harmless idioms (acceptable; document it).
4. **Padding inside a proving block is free.** Each intermediate state of a proving edge gets route distance
   `applied − i − 1` (`tactic_labels.py:103-108`), so every padding tactic of a block that is the only known proof
   earns +δ. Score and d(node) both shift, so nothing is gained, but proof length is not penalised either. Monitor
   tactics per proof against the SFT data.
5. **Gate (a) is tested repeatedly on one fixed benchmark** with continued, non-reset candidates, and its states come
   from the starting policy's distribution. Expect winner's-curse ratcheting: the published model gets selected on
   the noise of ~50–80 specific pairs, and later true gains become harder to pass. Log the cumulative number of gate
   tests. Re-searching the benchmark with the current policy every N retrains would also keep it on-distribution.
6. **The A/B decides on the probe set** (the first 250 probe problems), although DESIGN.md:794 says value models are not
   selected on the evaluation set. The A/B's v0 arm also repeats a probe-equivalent run. When both are due in the same
   pause, reuse the probe's v0 run as the reference arm.
7. **`phase_config_text` does not fill `value.model` from `serving.value_base_model`** (`loop.py:302-331`). Only
   `policy.model` is filled. If the two ever differ, the premerge marker mismatches and the publisher merges the
   adapter into a base it was not trained on (silently, on the CPU).
8. **A full reference-scoring pass every phase only for a metric.** With `kl_coefficient = 0`, from phase 2 onwards
   `reference_log_probabilities` loads the SFT adapter and scores every sequence (`policy_trainer.py:350-386`), about
   15% of the policy compute. Score a fixed subsample instead.
9. **Chunk explanations** (`data_rewrite/explanations.py`). The validators catch copies and line-by-line walkthroughs
   but not hindsight specifics (exact hint terms, constants), which is the intended rationalization style. Two smaller
   issues: (i) the teacher writes in named space with the names it chose itself, so the named arm's explanations are
   native and the numbered arm's are renamed back. This adds a small explanation-quality confound to the naming A/B
   in favour of named. Report the rejection rates per arm, or compare on the non-visible chunks only. (ii) The
   instruction allows ~80 words, while real explanations have a median of 199 characters. Compare the
   `explanation_characters` statistics with the real distribution before the SFT run, since length carries into RL
   sampling. Rejected visible-planned chunks become extra non-visible examples, which raises the non-visible share
   above `non_visible_share`.
10. **Stale-sample ratio.** Samples from trees spanning a pause are trained with ratios against the phase-start weights
    (documented, no correction). This is fine at the current lag. The new by-age agreement chart is the right monitor.
11. **DESIGN vs code on G with μ > 0.** DESIGN.md:540 gives G = (1 − μ)z + μq. The code gives a proof-graph G of 1
    and an off-graph G of μq (dead ends included, so with a v0-like p_dead a dead end earns ≈ +0.13). The tables
    match the code but the formula does not.
12. Carried over from review D and still open: no pruning of per-phase checkpoints (~0.5 GB of fp32 policy adapter
    per phase), and no automatic policy stop on collapse.

## Checked and fine

- **Data-parallel equivalence.** Global normalization per step, replay drawn identically on every rank and sharded
  under the global token mean, LoRA gradients summed before clipping, identical seeded init. A rank without
  micro-batches adds zeros and still enters every collective. The two-rank test passes. Rank-0-only gate and
  diagnostics with the others waiting in `broadcast_from_main` are safe under the 1 h timeout. An exception on one
  rank makes torchrun tear down the job; no hang.
- **Restart.** Stages are persisted. Publishing is idempotent through the trigger and the merge marker, and the
  premerged move into a fresh `.tmp` cannot nest. An EVALUATING restart reruns the due evaluations and swaps the
  value servers back. `kept_value` survives pruning.
- **Precision.** v2's adapter is on raw Qwen3.5-4B (`phase5_sft_visible_student_v2.toml`), so continuing it on the
  raw base is consistent. The KL reference equals `old` in phase 1. The fp32 lm_head runs with autocast disabled and
  full fp32 matmul (TF32 is not enabled anywhere). LoRA dropout is 0 in every config, so the first step's ratio of 1
  is a valid check.
- **Policy version per expansion.** It is read after `gate.enter()` and changes only while paused. One policy batch
  per expansion, one completion per sample, so the multiplicity matches the number of sequences.
- **Groups that need a policy proof, and thin off-graph evidence as unknown.** Implemented as described. A policy
  repeat of the sweep's tactic counts through `executed_edge_id`.
