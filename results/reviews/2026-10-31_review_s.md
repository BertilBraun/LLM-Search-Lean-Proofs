## Findings, by severity

### 1. (High) A failed inline claim proof scores −0.25, below the bare claim's −0.15

**Where.** `search/tactic_labels.py:197-218` (`with_unproved_claims`), together with the search's flattening:
- `lean/plans.py:174-265` (`_flatten_have`, `_flatten_bullet`);
- `search/search.py:116,647` (`flatten_blocks = True`).

**Scenario.**
- The policy writes the behaviour we want: `have h : A := by nlinarith [...]`, or `have h : A` followed by `· tac`.
- The search flattens the block. The opener `have h : A` is tactic 0 and the nested proof is a HAVE segment.
- When the nested proof fails, `apply_block` keeps the opener's state `[⊢ A, G with h]` as the valid prefix. The
  partial child is exactly the bare-have state.
- Labels: opener → UNPROVED_CLAIM (the anchor, −0.15), then the nested tactic → FAILING (non-anchor, −c).
  Score **−0.25**.
- The bare `have h : A` reaching the same node scores −0.15. A plain failing tactic scores −0.15.

**Repro.** `test_failed_inline_proof_scores_below_bare_have`, which prints
`[UNPROVED_CLAIM, FAILING, MASKED] -0.25` against `[UNPROVED_CLAIM] -0.15`.

Before the branch this sample had no score: `[UNKNOWN, FAILING]` had no anchor parts.

**Effect.**
- Attempting to prove the claim is now strictly worse than leaving it open.
- The attempt beats the bare claim only if the inline proof succeeds often enough. If the state after it is
  unknown (−0.075), break-even is about 57% success: p · (−0.075) + (1 − p) · (−0.25) > −0.15.
- So the fix still pays the policy for not attempting.

**Fix.**
- A `have … := by` (or `have` + bullet) whose nested proof failed is one failing source tactic. Label the opener
  FAILING and mask the rest, so the score is −0.15, like any failed attempt.
- Equivalently: in `with_unproved_claims`, skip a claim tactic when the edge failed and no applied later state
  returns to the count (the failure already charges the attempt), and do not add −c on top.
- Add a test for the flattened failing case.

**Confidence.** High: reproduced, and flattening is on in the loop's search config.

### 2. (High) Inside a block, a valid step into an unknown state costs about 1.1; a Lean error there costs 0.1

**Where.** `rl/grpo_groups.py:60-65` and `194-197`: UNKNOWN is now in `REACHED_STATE_LABELS` and in the gain case.
Encoded as intended by `tests/rl/test_advantages.py:68` and `:206`.

**Scenario.**
- A block's first tactic reaches a proof-graph state: R ≈ 0.85 + δ · progress.
- Its second tactic is valid and reaches a state nobody expanded (UNKNOWN, −0.075).
- The second tactic's gain is −0.075 − R ≈ **−1.125** in the repro.
- The same block with an erroring second tactic: −c = −0.1.
- Sample scores, in `test_valid_step_into_unknown_costs_more_than_an_error`:

  | Block | Score |
  |---|---|
  | `[PG, UNKNOWN]` | −0.075 |
  | `[PG, FAILING]` | 0.95 |
  | `[PG]` | 1.05 |

- The explanation tokens (score − b) and sequence credit see the same inversion.

**Effect.**
- The owner's ordering, unknown −0.075 above failure −0.15, holds only at the anchor.
- After the first tactic, a valid continuation into unexplored territory ranks about 1.0 below an error. This is the
  same class of inversion as the reward hack, in the other direction.
- Before the branch, the unknown continuation was untrained and the sample kept the prefix's R (1.05 > 0.95).
- The README's "costs about 10× a later error" was argued for well-explored off-graph states (evidence). It now
  applies to every unexpanded continuation, which is far more common. Blocks will be pushed to one tactic.

**Fix.** Keep the new anchor scoring, but at a non-anchor position treat UNKNOWN as before: gain None, and do not
advance `state`. Alternatively cap its drop at −c: `gain = max(R − state, −c)` on the local part. If the owner wants
the drop, it should be a recorded decision with this table.

**Confidence.** High that the behaviour is as described (reproduced, and the tests encode it). Medium that it is
unintended: the README states the drop, but not that it ranks valid continuations below errors.

### 3. (Medium) Goal-splitting tactics into a never-expanded child are UNPROVED_CLAIM (−0.15); a goal-preserving step there is UNKNOWN (−0.075)

**Where.** `search/tactic_labels.py:206-217` (any OFF_GRAPH or UNKNOWN state with more goals than before) and
`ClaimProofs.proved`, lines 95-98.

**Scenario.**
- Tactics that split the goal: `constructor`, `refine ⟨?_, ?_⟩`, `induction`, `cases` / `rcases` with alternatives,
  `by_cases`, `split_ifs`, `rw` with a side condition, `apply` with premises.
- If the child is never expanded, `own_fewest_goals` of the child is its own count, which is above "before". So the
  tactic is UNPROVED_CLAIM.
- That is "no evidence", not "unproved". A never-expanded child is the most common case in a budgeted search.
- Repro `test_constructor_into_unexpanded_child_is_unproved_claim`:

  | Tactic | Label | Score |
  |---|---|---|
  | `constructor` | UNPROVED_CLAIM | −0.15 |
  | goal-preserving `rw` | UNKNOWN | −0.075 |

- In single-step mode (`max_expansions = 1`), no child is ever expanded. There every goal-adding tactic that does not
  hit a reference state is −0.15.

**Fix.** Restrict the rule to the bare-claim shape the hack used: the state's first goal has the before state's
context, and the remaining goals equal before with one more hypothesis (the shape `added_hypotheses` already
recognizes). Alternatively require evidence: the claim node expanded (dead end, or ≥ `off_graph_min_expanded_nodes`)
before calling it unproved.

**Confidence.** High on the behaviour. The severity depends on how often splits land in unexpanded children; measure
it on a phase's trees.

### 4. (Medium) Closed-form rule: useful facts are REDUNDANT when the context has no locals, or when they are about global constants

**Where.**
- `lean/hypotheses.py:98-100` (`closed_form`: no context name mentioned) and `132-139`;
- `search/tactic_labels.py:250-251`.

**Scenario.** All of these are true in `test_useful_hypotheses_are_closed_form`:

| Context | Hypothesis judged closed-form |
|---|---|
| no locals (`⊢ 2 ^ 10 % 7 = 2`, common in mathd_numbertheory-style problems) | every addition, e.g. `h : 2 ^ 10 = 1024` |
| no locals | `h : Real.sqrt 8 = 2 * Real.sqrt 2` |
| has locals | `hπ : 3 < Real.pi` |
| has locals | `Fact (Nat.Prime 7)` (needed for the `ZMod 7` field instance) |
| no locals, target `⊢ ∀ x, …` before `intro` | bound-variable lemmas such as `h : ∀ (x : ℝ), (x - 1) ^ 2 ≥ 0` |

- Off the proof graph these become −0.15 (anchor) or −c (later): below UNKNOWN, equal to a failure.

Identifier matching itself is right on what I tried:
- `h₀.1`, `↑n`, `x⁻¹`, `(x : ℝ)` and `f x` count as mentions;
- `x'`, `x✝`, `xs` and `Real.x` do not.

**Fix.** Make "closed form" literal-only: no identifiers at all besides numerals, casts and type names (`ℝ ℕ ℤ ℚ ℂ`).
That still catches `0 < (1:ℝ)` and `0 < ((0:ℝ))`. Also skip the rule when the before state has no hypothesis names.

**Confidence.** High on the behaviour. Medium on the impact, which depends on the share of no-local statements in
the curriculum.

### 5. (Medium) The hack has escapes that keep −0.075 > −0.15: `suffices`, and `have` + `swap`

**Where.** `tactic_labels.py:206-211`: the rule needs more goals than before. `ClaimProofs.proved` counts goals, not
which goal closed.

**Scenarios.** Both are reproduced:
- `suffices h : C by linarith` replaces the goal with the claim without adding one. It is UNKNOWN at −0.075, against
  −0.15 for the bare have (`test_suffices_escapes_the_unproved_claim_rule`).
- `have h : C`, then `swap`, then a closer of the main goal: the block returns to one goal, so the claim counts as
  proved. All three tactics are UNKNOWN (`test_swap_escapes_the_unproved_claim_rule`). The README names `swap`; it
  does not name `suffices`.

**Effect.**
- An unproved claim left as the goal still beats a genuine attempt that fails.
- The habit monitor would not see the move: `is_bare_have` matches only a first tactic starting with `have` without
  `:=`. It misses `suffices`, `have … := ?_` and claims after the first tactic.

**Fix.**
- Monitor `suffices` / goal-replacing openings and claims at any position.
- Consider applying the claim rule to a state whose target is new and that no reachable state reduces below its own
  count.
- The deeper lever is unknown vs failure (−0.075 vs −0.15). It is the owner's call, but it leaves half the original
  incentive.

**Confidence.** High on the mechanics. Medium on whether the policy will find these.

### 6. (Medium) Dead ends score 0, above unknown (−0.075)

**Where.** `grpo_groups.py:168-169` and `tactic_labels.py:156-157`. Shown by `test_grpo_groups.py:75` (dead end
score 0.0).

**Scenario.**
- A dead end is a state the search expanded where nothing usable came out. That is the strongest negative evidence
  the tree has.
- It now ranks above a state nobody looked at.
- A valid goal-preserving step to a false goal (e.g. a `suffices` to a false claim) that gets expanded once earns 0,
  the best score short of the proof graph.
- Before the branch, unknowns were unscored, so this ordering did not exist.

**Fix.** Score dead ends at `unknown_local` or `no_progress_local`. Keep 0 (μ · q) for expanded off-graph states with
live subtrees.

**Confidence.** Medium: certain on the ordering, uncertain how often the search expands such states.

### 7. (Medium-Low) A claim proved elsewhere in the tree is still "unproved"

**Where.** `ClaimProofs` (`tactic_labels.py:74-98`) only looks at states reachable from the claim node.

**Scenario.**
- `have h₂ : x = -4` is never expanded.
- A sibling `have h₂ : x = -4 := by linear_combination …` reaches the proof graph.
- The bare have is UNPROVED_CLAIM although its claim is proved, and its continuation `G with h₂` is on the proof
  graph (`test_claim_proved_by_a_sibling_is_still_unproved`).

**Fix.** For a bare-claim-shaped state `[⊢ A, G']`, treat the claim as proved when `goal_key(goals[1:])` is a
node's key or is in `steps_by_key`.

**Confidence.** High.

### 8. (Medium) The reference backfill at start: blocking, all-or-nothing, and repeated

**Where.** `rl/loop.py:846` (awaited before the heartbeat, `clear_stale_handoff` and the server check), `1318-1333`,
and `health_checks.py:137`.

**Problems.**
- **Cost.** It reads every tree of the `reference_phases` (2) phases with texts. For each tree it recomputes
  `edge_labels` and `forward_successors`, plus `goal_parts` on every policy state pair. I could not time it (no trees
  locally). At a few thousand trees per phase it can be minutes with idle GPUs and no status heartbeat. Measure it on
  the node before the restart, e.g. time `block_habits` over one phase's trees, or run it as a background task
  instead of awaiting it.
- **All-or-nothing.** One unreadable tree (a truncated gzip from a crash) raises inside the generator. The whole
  backfill is then abandoned: the alert is logged and the habit checks have no reference.
- **Repeated.** A phase that stays `None` (missing trees, no judged blocks) is re-measured and appended again at every
  start.
- **Dashboard.** The appended lines go only to `paths.health`, not through `self.writer`. The dashboard's habit charts
  have no reference-phase points.

`read_health_history` keeps the last line per phase, so duplicate lines are harmless otherwise.

The test is genuine: with `backfill_reference_habits` patched to a no-op, it fails.

**Fix.**
- Skip unreadable trees per file (and count them).
- Run the backfill as a task, not before the servers start.
- Write the record through the monitoring writer too.
- Mark a phase as measured even when the result is None.

**Confidence.** High on the mechanics, low on the actual duration.

### 9. (Low) Single-step: closed-form reference steps are never relabelled to the proof graph

**Fix.** Include REDUNDANT_HYPOTHESIS in the relabel set when the key is a reference state.

**Confidence.** High; impact limited to the single-step comparison.

### 12. (Info) Group composition, normalisation, trigger, trainer

- **`require_policy_proof`.** Unchanged: groups still need a PROOF_GRAPH sample, and scored unknowns do not count as
  one.
- **Normalisation.** There is no per-group std normalisation; advantages are raw differences. With unknowns in the
  baseline, b drops in solved groups, so proof-graph samples' advantages and the total gradient magnitude grow.
  Expect a larger KL step at the same lr. Watch the KL and clip alerts on the first phases.
- **Phase trigger.** It is `minutes ≥ min_sampling_minutes and groups ≥ min_trainable_groups` (`loop.py:810`), so
  more trainable groups do not shorten phases.
- **Trained sequences and timeouts.** Unknown-only samples now train, so expect a longer train step. The persistent
  trainer's timeout restarts at `first_train_timeout_minutes` (120) in a new job, so the first phase is safe.
- **Config keys.** `from_json_object` rejects unknown keys, so a trainer on old code would fail on
  `unproved_claim_local` / `unknown_local`. The persistent trainer is started by the loop and stops when the loop's
  process is gone, so restarting the loop with the new code is enough.
- **Old index lines.** They lack `habits`, parse with the default (zeros), and measure as None.

## Verdict

**Blockers: 1 and 2.**
- Both create new cases where a valid or attempted step scores below a failure or below the bare claim. That is the
  defect this branch exists to remove, and both hit common block shapes:
  - one-line `have … := by tac` with a failing proof;
  - any multi-tactic block whose tail leaves the proof graph into unexplored states.
- Finding 1 is a small change in `with_unproved_claims` / the flattened-opener handling.
- Finding 2 is a one-line choice in `judged_in_block`: non-anchor UNKNOWN untrained, or its drop capped at −c.

**Should fix before deploying, not strictly blocking: 3 and 4.**
- 3 is a narrower claim shape.
- 4 is a literal-only closed form.
- Both mislabel good tactics as −0.15 on common patterns.

**Can follow:** 5-12. For 8, time the backfill on the node first; if it is more than a few minutes, run it in the
background.
