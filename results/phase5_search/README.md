# Row 5: thinking vs non-thinking search at equal generated tokens

Full miniF2F-valid, the bootstrap policy (`phase5_sft_bootstrap_r1`, merged) and value v0 (merged), one instance of
each per GPU, 120 searches pinned to 40 CPUs, overlap and early value scoring, the 7-tactic sweep; priority
f = h + 0.25·depth (no policy prior in any arm: a thinking candidate's log-probability includes its reasoning, so
the prior would penalize thinking steps by tens of steps). Budget per theorem: 96,000 generated tokens (about 50
thinking expansions at n = 8), up to 1,000 expansions, 900 s. Configs
`experiments/configs/reasoning/phase5_search_bootstrap_*.toml`; node-monitor windows in `monitor/` (busy: 120–600 s;
token and sample rates are those of GPU 0's policy server). 2026-10-13 00:45–01:36 UTC.

- **At equal generated tokens thinking loses at every budget**: solved within 2k / 5k / 10k / 50k tokens per theorem is
  58 / 109 / 133 / 151 for T against 144 / 149 / 152 / 156 for N and 137 / 147 / 155 / 159 for N16, and T ends 4–7
  theorems behind. Neither non-thinking arm reached the 96k budget on average (8.9k and 12.4k tokens per theorem):
  they stop on proofs, frontier exhaustion or the wall clock long before.
- **Per expansion thinking is as good as not thinking** (solved within 8 / 16 / 32 expansions: T 139 / 148 / 152,
  N 142 / 146 / 149, N16 145 / 149 / 151), but each thinking expansion costs ~1,900 generated tokens against ~170 (N) and
  ~300 (N16), and the token budget stops T after ~13 expansions on average.
- **Resources are inverted**: T is GPU-bound (both GPUs ~96%, 194 running sequences on GPU 0's policy server) and uses
  18 CPU cores and 49 Lean-seconds per theorem; N and N16 are Lean-bound (43.5 of 46 cores, 214–233 Lean-seconds
  per theorem). Per wall-clock second per theorem T is behind too (solved within 60 / 120 / 300 s: T 115 / 134 / 146,
  N 143 / 147 / 152, N16 138 / 146 / 151); all three runs took ~17 minutes for the split.
- Against row 4 (157/244, SFT v2, 600 s, 40 searches), the bootstrap policy without thinking is within noise (156 at
  n = 8, 159 at n = 16); the bootstrap training did not hurt the non-thinking search.

## Recommendation

**The expert-iteration loop should run without thinking**, at n = 16 if the stages' token budgets allow it, n = 8
otherwise: at equal generated tokens non-thinking solves more at every budget, and thinking's ~11× tokens per
expansion are not bought back by better steps. Thinking does have one property the loop could use later: it needs a
fifth of the Lean CPU per theorem, so on a CPU-bound node a thinking search on otherwise idle GPU capacity would be
nearly free in Lean; with both GPUs already ~96% busy in the non-thinking runs (value scoring), that capacity does not
exist on this node.
